# Contributing

Thank you for contributing. This repository is designed to make the open-source workflow approachable for beginners.

## Before opening a pull request

1. Check existing issues and pull requests to avoid duplicate work.
2. Create a branch from the latest `main` branch.
3. Keep the change focused on one improvement.
4. Review the changed files and remove unrelated edits.

## Branch and commit style

Use a short branch name that explains the purpose:

```text
docs/improve-setup
feature/add-example
fix/correct-output
```

Write commit messages in the imperative form, for example:

```text
docs: clarify contribution steps
feat: add a Python example
fix: correct the sample output
```

## Pull request checklist

- Describe what changed and why.
- Include testing instructions when applicable.
- Add screenshots for visible UI changes.
- Confirm that no secrets or personal files are included.
- Respond respectfully to review feedback.

Small, clear pull requests are easier to review and more likely to be merged quickly.
